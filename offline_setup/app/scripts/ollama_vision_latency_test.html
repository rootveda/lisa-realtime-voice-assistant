Ollama vision latency (standalone test)

Not the main assistant — this page is only for the one-off test server. From offline_setup/app run uv run python scripts/ollama_vision_latency_serve.py then open http://127.0.0.1:8765/ (default; use --port to change). Your browser sends one webcam frame to /api/vision/preview on that small process; it uses the same vision_caption / Ollama env as the stack. Camera needs a secure context (HTTPS, or localhost / 127.0.0.1).

Latency / “trimmed” captions (server env)

This panel shows the full caption text returned by the server. If you see a line that stops mid-sentence (“looking at the”, “shoulders/”), that is not the browser cutting it — the model hit the token budget (VISION_CAPTION_MAX_TOKENS, caps output length). Preamble phrases like “Examine the Image:” use those tokens before the actual scene description.

A static webcam still produces a slightly different JPEG every capture (compression, timing), and default sampling adds variance — so wording and length can change run to run even for the same view.

For fuller sentences: raise tokens, e.g. export VISION_CAPTION_MAX_TOKENS=768 before starting the test server; for steadier text on a fixed scene try VISION_CAPTION_TEMPERATURE=0.2. Lower tokens (e.g. 220) speeds up but cuts mid-sentence more often. For lower latency when captions already come from native Ollama: export VISION_CAPTION_OPENAI_COMPAT=0 (one VLM call instead of compat then native). Most delay is still Ollama inference. See docs/stack-start-stop.md.
